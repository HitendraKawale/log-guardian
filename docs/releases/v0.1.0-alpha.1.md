# v0.1.0-alpha.1: evidence-first security review

Log Guardian's first tagged prerelease makes the no-model security review workflow the
starting point. Import a bounded window of gateway and authentication logs, inspect linked
requests, and read cited facts with explicit unknowns. Optional AI is a separate action,
not a prerequisite for understanding the records.

This is a source release for local evaluation. It is not a hosted service, a validated
attack detector or a production-ready deployment. No container image is published with
this release.

## Included

- Owner-configured nginx JSON and application-auth JSONL imports. Scope is capped at one
  hour, four sources/services and 1,000 input records, with additional byte limits.
- Saved source snapshots, duplicate/conflict handling and exact request-ID correlation.
  Uploaded strings cannot redefine source identities or request namespaces.
- Deterministic assessments that review every unique saved record and disclose the
  displayed/omitted counts. Policy 1 displays at most 12 facts, with bounded citation data.
- Browser imports, history, keyboard-accessible citations and mobile layouts. Review keys
  stay in page memory and must be entered again after reload.
- Optional, separately authorized AI execution over the saved case only. The model selects
  evidence and allowed codes; server-side validation and rendering determine the report.
  Invalid selections fail without repair or automatic retry. AI failure does not erase the
  deterministic assessment.
- The existing operational log platform, investigation research and Python agent recorder.
  Their historical metrics are not security-detection accuracy claims.

## Executed evidence

Five final browser-driven scenarios used a running, locally instrumented OWASP Juice Shop:
normal login/cart, wrong password, two failures followed by success, guest browsing/cart,
and a deliberate missing-auth export. The application emitted the authentication outcomes;
the driver did not synthesize them.

Across five reviews, Log Guardian checked 182 records representing 154 unique source
records. The missing-auth case reused the normal gateway window. Authentication remained
unknown without the auth records, even though the browser login had succeeded. A separate
check confirmed nginx overwrites caller-selected request IDs. The business test created
zero Investigation rows and made no model calls.

The [experiment archive](../verification/juice-shop-business/README.md) includes original
source logs, expected-versus-observed results, screenshots, source/image identifiers,
patches, resolved dependency metadata, runnable checks and SHA-256 hashes. It excludes
runtime credentials, authentication responses and application databases.

Recorded Log Guardian checks at this checkpoint:

- 840 offline tests and six demo tests passed.
- 17 security-review browser tests passed.
- Lint and formatting checks passed.
- The standalone archive verifier checked counts, links, source fields, citations and
  unknowns without importing Log Guardian's assessment builder.

The archive also preserves failures. Four earlier driver attempts needed corrections.
Juice Shop's complete API suite had the same 21 failures before and after instrumentation,
including internet checks blocked by runtime isolation. The minimal gateway produced a
Socket.IO WebSocket upgrade error. These are not reported as passing checks.

The separate [typed AI experiment](../../evals/results/2026-09-27-typed-business-live/README.md)
completed two of four cases and rejected two. No new paid model evaluation was run for
this release. The controlled shop test is integration evidence, not independent diagnosis
accuracy or proof of customer usefulness.

## Try it

Use the [local security-review guide](../security-log-review.md#local-setup). It includes
source configuration, database migration, loopback API/frontend commands and a six-record
authored example. Keep `INVESTIGATION_API_KEY` and `OPENAI_API_KEY` empty and do not start
a worker for no-model review. Use free local ports rather than stopping another service.

The [recorded walkthrough](../../frontend/media/security-review.webm) demonstrates the
older scripted-provider flow. Its provider response and usage are simulated; it is not the
Juice Shop experiment or a live-model evaluation.

## Upgrade and execution safety

- Back up the database and run `alembic upgrade head` from `services/ingestion-service`
  using the repository environment. Migrations through `0008` are required.
- Upgrade the API and worker together before enabling optional AI execution. Workflow v2
  bindings reject incompatible queued security runs before provider dispatch. Terminal
  historical reports stay available; this release does not migrate or retry old runs.
- Configure separate review and execution keys. Opening a case or requesting its
  `/security/cases/{id}/assessment` endpoint does not queue work.
- Starting a provider-configured worker can spend on queued investigations. Existing
  per-run request/tool/time/byte/cost bounds are not an account-wide billing guarantee.
  Historical research allowances are closed and do not authorize another run.

## Limits

HTTP status is not an authentication result. Successful authentication is not compromise.
Addresses do not identify people, and timestamp order does not prove causality. Supplied
records do not establish collection completeness, source authenticity or business impact.

Review access is single-owner, not multi-tenant. Automated retention and validated
production capacity are absent. The importer requires prescribed formats rather than
arbitrary logs. The shop hook covers password-login decisions, not complete MFA/OAuth,
orders or payments. Default infrastructure still needs deployment-security work.

The next milestone is a supervised, owner-approved review with a real business, measuring
setup effort, correctness and usefulness against its existing process.
