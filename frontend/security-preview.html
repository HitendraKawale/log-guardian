Review gateway requests and authentication outcomes before drawing a conclusion. This recording follows the working import, timeline and explicitly authorized investigator flow.

Walkthrough transcript

  1. Connect with a review key. The server supplies the registered gateway and authentication sources. Uploaded text cannot choose a trusted identity or request namespace.
  2. Import six authored records for a ten-minute window. The saved review shows three linked requests, two authentication failures and one success. Importing queues no model work.
  3. Open the first gateway citation, which records HTTP 200. Its linked authentication record explicitly says failure. HTTP status and auth outcome are different evidence.
  4. Enter a separate investigation key and acknowledge provider sharing. Explicitly start the case-bound investigation. In this recording, a scripted provider supplies the draft.
  5. Inspect the unverified draft and open its citation. The worker delivered that record; the citation alone does not establish that the model's reasoning is correct.
  6. Return to the case limits. One successful login does not prove compromise. Data access, actor identity and AI involvement are unestablished. Collection completeness and clock alignment remain unknown.

What this demonstrates

A tested evidence-review workflow, not credential-stuffing detection accuracy or a real customer incident. The application does not automatically block requests or disable accounts. Model drafts require human review.
